# 持续施工、恢复与人类接管协议

## 自动继续

当 `task_complete=false`、存在下一合法动作、没有合法人类门禁且不存在不可恢复阻塞时，状态必须是 `AUTONOMOUS_CONTINUATION`。阶段通过、测试通过、子任务完成都只是 checkpoint，不得变成等待用户“继续”的理由。若 agent 形成被动停止语句，记录 `ILLEGAL_PASSIVE_STOP`，指标 `unnecessary_human_wait_count` 加一，并执行下一合法动作。

## 合法等待

只能为 `HUMAN_AUTHORIZATION_REQUIRED`、`HUMAN_BUSINESS_DECISION_REQUIRED`、`CONSTRAINT_CONFLICT_REQUIRES_HUMAN`、`RECOVERY_EXHAUSTED`、`EXTERNAL_HUMAN_ACTION_REQUIRED`、`USER_ONLY_ACCEPTANCE_REQUIRED`、`USER_REQUESTED_PAUSE` 或 `FINAL_COMPLETE` 等待。除 FINAL_COMPLETE 外，必须带完整 `HUMAN_RECOVERY_PACKAGE`；没有包即为非法等待。模型资源不足的暂停走 `MODEL_HANDOFF_REQUIRED`（等待继任模型而非用户，需完整 `MODEL_HANDOFF_PACKAGE`，规格见 [`MODEL_HANDOFF_PROTOCOL.md`](MODEL_HANDOFF_PROTOCOL.md)）。

## 恢复

“继续 / continue / resume / 已处理”只能写 `RESUME_REQUEST`，不是 blocker 已解决的证据。恢复前读取合同、阶段、Last Known Good、失败证据和当前治理环境；重新核验 blocker、Git HEAD、worktree、runtime、权限、合同哈希和 Evidence identity。失败则写 `RESUME_VERIFICATION_FAIL` 并保持暂停；通过则写 `RESUME_VERIFICATION_PASS`，先重跑原失败 Gate 与 Regression，随后自动继续。

## Recovery ladder

失败先冻结 Evidence，分类为 CODE、CONFIG、ENVIRONMENT、DATA、PERMISSION、CONTRACT、EXTERNAL_SERVICE、RUNTIME、EVIDENCE 或 UNKNOWN。每个自动恢复尝试有明确预算；成功必须含原失败的重新验证和 Regression。预算耗尽后依次评估安全回滚与不扩 Scope 的替代路径（机械判定见 [`RECOVERY_ESCALATION_SPEC.md`](RECOVERY_ESCALATION_SPEC.md)）；仍不能恢复才输出完整人类恢复包并进入 `SUSPENDED_AWAITING_HUMAN`。

Last Known Good 至少记录 task_id、stage_id、contract_hash、git_head、worktree_identity、runtime_identity、last_passed_gate、evidence_anchor 和 timestamp。

## 资源守卫与模型交接

开工前与每个 Stage 边界执行 `EXECUTION_RESOURCE_GUARD`（规格见 [`EXECUTION_RESOURCE_GUARD_SPEC.md`](EXECUTION_RESOURCE_GUARD_SPEC.md)）：只使用真实可见信号，不可见即 NOT_AVAILABLE 禁止估算；YELLOW 不开大型新 Stage 并准备 Checkpoint；RED 按"完成原子单元→Checkpoint→交接"或"停止新写入并标记 UNVERIFIED_PARTIAL_WORK"收口，生成完整 `MODEL_HANDOFF_PACKAGE` 进入 `MODEL_HANDOFF_READY`。继任模型接管必须先机械核验真实状态（`verify_handoff`），全部一致记录 `MODEL_HANDOFF_COMPLETED` 后沿用原 task_id 继续；任一不一致记录 `HANDOFF_VERIFICATION_FAIL`，禁止继承（连续性规格见 [`LONG_RUNNING_PROJECT_CONTINUITY_SPEC.md`](LONG_RUNNING_PROJECT_CONTINUITY_SPEC.md)）。
