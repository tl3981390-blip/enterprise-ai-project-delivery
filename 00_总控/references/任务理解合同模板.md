# 任务理解合同（Task Understanding Contract）模板

> 生成时机：UNDERSTANDING 阶段结束。必填字段缺一不可；逐项标记来源。JSON Schema：`共享/schema/task_understanding_contract.schema.json`。

## 合同字段（每项须填）

| 字段 | 含义 | 必填 |
| ---- | ---- | ---- |
| task_id | 任务唯一标识 | ✅ |
| user_real_goal | 用户真正要解决的问题 | ✅ |
| business_goal | 为什么做（业务价值） | ✅ |
| final_deliverable | 最终交付物 | ✅ |
| current_state | 当前项目已有什么 | ✅ |
| completed_scope | 已经完成到什么程度 | ✅ |
| work_scope | 本轮工作范围 | ✅ |
| explicit_non_goals | 明确非目标 | ✅ |
| allowed_modify | 允许修改范围 | ✅ |
| forbidden_modify | 禁止修改范围 | ✅ |
| allowed_tools | 允许工具 | ✅ |
| forbidden_tools | 禁止工具 | ✅ |
| key_constraints | 关键约束 | ✅ |
| success_criteria | 成功标准 | ✅ |
| acceptance_criteria | 验收标准 | ✅ |
| evidence_requirements | Evidence 要求 | ✅ |
| known_risks | 已知风险 | 推荐 |
| blocking_unknowns | 阻塞性未知项（存在→Gate FAIL） | ✅ |
| non_blocking_unknowns | 非阻塞性未知项（记录不阻塞） | 推荐 |
| provenance | 每个结论来源（见下） | ✅ |
| understanding_status | UNDERSTANDING_COMPLETE / UNDERSTANDING_BLOCKED / BLOCKED | ✅ |

## 来源分级（provenance）

| 来源码 | 含义 | 可升级为合同事实 |
| ---- | ---- | ---- |
| `USER_EXPLICIT` | 用户当前明确提出 | ✅ |
| `USER_PREVIOUSLY_CONFIRMED` | 此前明确确认且仍有效 | ✅ |
| `PROJECT_EVIDENCE` | 真实项目/文件/Git/代码/配置支持 | ✅ |
| `SYSTEM_OBSERVED` | 运行环境真实观察 | ✅ |
| `AI_INFERRED` | AI 推断 | ❌ 重大范围/权限不能仅靠它 |

## 锁定后效力

合同锁定后即成为后续所有阶段的对账基准（PLAN 对账 + DRIFT_CHECK）。重大变更必须回到本模块更新合同并经用户确认，禁止静默改合同。
