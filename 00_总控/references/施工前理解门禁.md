# 施工前理解门禁（PRE_EXECUTION_UNDERSTANDING_GATE）判定规则

> 本文件定义「理解完成与否」的判据。脚本只做结构与字段检查，业务含义是否理解由 AI 判定。

## 一、何时触发

任何任务进入 Skill 后、或任何阶段推进到将要发生写改动作前，都必须先过此门禁（在 UNDERSTANDING 状态内）。在此状态禁止 WRITE/EDIT/DELETE/EXECUTE/DEPLOY/MIGRATE/INSTALL/ALTER。

## 二、UNDERSTANDING 状态允许的动作

```text
READ  SEARCH  INSPECT  ANALYZE  COMPARE  SUMMARIZE  VALIDATE_EXISTING_STATE
```

## 三、理解完成的六个必要条件

| # | 条件 | 判据 |
| -- | ---- | ---- |
| 1 | 目标明确 | user_real_goal + business_goal + final_deliverable 均有内容且来源非纯 AI_INFERRED |
| 2 | 当前状态明确 | current_state + completed_scope 有 PROJECT_EVIDENCE 支撑或用户确认 |
| 3 | 工作范围明确 | work_scope + explicit_non_goals 明确 |
| 4 | 禁止项明确 | forbidden_modify / forbidden_tools 明确 |
| 5 | 成功标准明确 | success_criteria / acceptance_criteria 可判定 |
| 6 | 关键约束明确 | key_constraints 明确 + 无阻塞性未知项 + 无重大内部冲突 |

全部满足 → `UNDERSTANDING_COMPLETE = true` → `READY_TO_PLAN`。否则 → `BLOCKED`（或 `UNDERSTANDING_BLOCKED`，需人工/用户澄清，禁止自行推断补全）。

## 四、阻塞性 vs 非阻塞性未知项

| 类型 | 例子 | 处理 |
| ---- | ---- | ---- |
| 阻塞性 | 新项目 or 在用生产系统；能不能访问数据源；权限边界 | 未解决 → 禁止施工 |
| 非阻塞性 | 按钮颜色；措辞偏好 | 记录，不阻塞 |

判定原则：该未知是否**实质改变施工方向/范围/权限**。是→阻塞；否→非阻塞。

## 五、来源信任规则

- `AI_INFERRED` 不能冒充用户要求（USER_EXPLICIT / USER_PREVIOUSLY_CONFIRMED）。
- 重大范围、权限、目标若仅由 AI_INFERRED 支撑 → 须返回用户确认，不得自动升级为合同事实。

## 六、失败处理

- Gate FAIL → 保留 `understanding_gate_result`（FAIL + 缺失项列表 + 证据）。
- 禁止“测试失败→改报告为 PASS”。
- 阻塞性未知未解决 → `BLOCKED`，请求人工/用户，输出证据。

## 七、Verification

- 结构：`共享/scripts/check_understanding_gate.py --contract contract.json`（必填字段 + 来源完整性）。
- 业务含义：AI 据此文件与八问人工判定，脚本不替代。
